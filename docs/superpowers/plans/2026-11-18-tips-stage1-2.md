# 段1・段2にもコツを出す 手順書

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** コツを出す部品を1つにまとめ、段1（答えたあと）と段2（各手順の「はじめる」の画面）にもコツを出す。

**Architecture:** `src/ui/tipNote.js` に `tipNote(stageKey, index)` を作る。段3〜5のそれぞれの `tipNote()` をこれに置きかえ、段1・段2から新しく呼ぶ。

**Tech Stack:** 素の JavaScript、vitest ＋ jsdom（いまのまま）

**Spec:** `docs/superpowers/specs/2026-11-18-tips-stage1-2-design.md`

## Global Constraints

- コツの文（`src/data/tips.json`）は変えない
- 見た目は「💡 」＋コツの文。5つの段で同じ
- 画面の文に禁止の言葉（`src/logic/words.js` の `findBanned`）を出さない
- コードは短い関数と日本語の「なぜ」コメント（`CLAUDE.md`）

## Review Focus

1. **コツの一覧が空**（将来ある段のコツを消したとき）：何も出さず、画面は止まらない（Task 1 のテスト）
2. **index が一覧の数より大きい・0**：くり返して、必ず一覧の中の1つを出す（Task 1 のテスト）
3. **段2で「やり直す」をした**：同じ手順の画面にもどっても、すぐ前と同じコツが続かない（Task 2 のテスト）
4. **段1の答える前の画面**：コツは出さない（音を聞くじゃまをしない）（Task 2 のテスト）
5. **段3〜5**：これまでどおり、1回ごとにコツが出る（Task 1 で今あるテストが通ること＋1つ確認）

### Task 1: コツの部品をまとめる

**Files:**
- Create: `src/ui/tipNote.js`
- Modify: `src/screens/stage3.js:84-88`, `src/screens/stage4.js:119-123`, `src/screens/stage5.js:103-106`（それぞれの `tipNote()` を消し、新しい部品を呼ぶ）, `src/styles.css`（`.tip` を1つ。色は `:root` のトークンだけ）
- Test: `tests/ui/tipNote.test.js`

**Interfaces:**
- Produces: `tipNote(stageKey: 's1'|'s2'|'s3'|'s4'|'s5', index: number, list = tips[stageKey]): HTMLElement[]`
  - 一覧が空・無い → `[]`
  - それ以外 → `[p.note.tip]` 1つ。文は `'💡 ' + list[((index % n) + n) % n]`
  - `list` は省略できる（テストで空の一覧などを渡すため）

- [ ] **Step 1: 失敗するテストを書く**（`tests/ui/tipNote.test.js`）
  - `tipNote('s3', 0)[0].textContent === '💡 ' + tips.s3[0]`、クラスに `tip` がある
  - `tipNote('s3', tips.s3.length)` は `tips.s3[0]`（くり返す）。`tipNote('s3', -1)` は最後のもの
  - `tipNote('s1', 0, [])` は `[]`
  - `tipNote('s1', i)` を i=0〜9 で：となり同士が同じ文にならない
- [ ] **Step 2:** `npx vitest run tests/ui/tipNote.test.js` → FAIL（モジュールが無い）
- [ ] **Step 3:** `src/ui/tipNote.js` を書き、段3〜5を `...tipNote('s3', tries)` などに置きかえる（いま渡している数はそのまま）
- [ ] **Step 4:** `npx vitest run` → すべて PASS（段3〜5の今あるテストを含む）。段3のテストに「コツの文が 💡 つきで出る」を1つ足す
- [ ] **Step 5: Commit** `git commit -m "コツを出す部品を1つにまとめる"`

### Task 2: 段1・段2にコツを出す

**Files:**
- Modify: `src/screens/stage1.js`（`showFeedback`）, `src/screens/stage2.js`（`showStep`）
- Test: `tests/ui/stage1.test.js`, `tests/ui/stage2.test.js`

**Interfaces:**
- Consumes: Task 1 の `tipNote(stageKey, index)`

- 段1：`showFeedback` の `note(message)` のすぐ下に `...tipNote('s1', answered() - 1)`。答える前の画面（`showQuestion`）には出さない
- 段2：`showStep` の `note(step.text)` と「はじめる」の間に `...tipNote('s2', shownSteps)`。`shownSteps` は `showStep` を呼ぶたびに1つ増える数（画面を開くたびに 0 から）

- [ ] **Step 1: 失敗するテストを書く**

  - stage2：手順1の画面に `💡 ` + `tips.s2[0]`。手順1を録り終えて手順2の画面に `tips.s2[1]`。手順2で「やり直す」→ 前の画面と別のコツ
  - 段1の答えのあとの画面・段2の手順の画面に `findBanned` が空
- [ ] **Step 2:** `npx vitest run tests/ui/stage1.test.js tests/ui/stage2.test.js` → FAIL
- [ ] **Step 3:** 上のとおりに書く
- [ ] **Step 4:** `npx vitest run` → すべて PASS。`npm run build` も通る
- [ ] **Step 5: Commit** `git commit -m "段1・段2にもコツを出す"`
