## 段6 ①（ファイルで練習）の状態
- できていること：曲ファイル（と、あれば歌声だけのファイル）を足す → お手本の線を作る（進み具合つき）→ 曲の画面で線をなぞって区間を選び、保存（5つまで）→ ▶ 聞く（速さ 1／0.75／0.5倍・スピーカーで）→ ● 歌う（毎回イヤホンの確認 → 線グラフと合いぐあいの「目安」）。「歌声だけの ファイルの 作り方」の案内画面（vocalGuide）つき
- 曲ファイル・お手本の線は IndexedDB（スマホの中だけ。バックアップに入れない）。録った声は保存しない
- 数字の目安は `src/logic/config.js` の `CONFIG.stage6` に集めてある（マイクの遅れ `latencyMs` など）
- テスト：部品のテスト＋画面の流れ `e2e/stage6.spec.js`（偽の曲 `e2e/fixtures/song.wav`、作り直しは `node scripts/make-fixture.mjs`）。電波なしで曲の画面が開くことも確認済み

## 段6 ②（YouTube で練習）の状態
- できていること：曲を足すとき YouTube のアドレスだけでもよい（曲ファイルなしの曲。一覧に ▶ の印）→ YouTube の曲の画面（`songYt`）で、公式の埋め込みプレーヤーを読み込む → 「ここを 始まりに／終わりに」で区間を決める（0.5秒ずつの微調整つき）→ 「▶ 区間を くり返す」→ 速さ（1／0.75／0.5倍。YouTube が選べない速さは実際の速さを表示）→ 区間の保存（YouTube 用は `ytSections` で別に持つ）→ イヤホンの確認 → 「● 歌う」（マイクは歌うときだけ開く）→ ゆれの目安（少なめ・ふつう・多め。音の変わり目で区切ってから測る）・声の地図より高い／低い所が「ありました（目安）」（数は出さない。合わせて 200ms 以上のときだけ）
- 曲のダウンロードはしない。YouTube につながるのは、この画面の公式プレーヤー（`https://www.youtube.com/iframe_api`、プレーヤーは youtube-nocookie.com）だけ。電波がないときは案内を出す（`ytOffline`）
- きろく：YouTube の練習は `kind: 'yt'` で、「好きな 曲：○○（YouTube）　N回 練習」（成功数・合いぐあいは出さない）
- 場所：`src/audio/ytPlayer.js`（公式 API を包む唯一の場所）、`src/screens/stage6Yt.js`、`src/logic/ytClock.js`、`src/logic/youtubeUrl.js`
- テスト：部品のテスト＋画面の流れ `e2e/stage6Yt.spec.js`（実際のネットにはつながず、`page.route` で偽の YouTube プレーヤーに差し替える）
- **未確認**：YouTube の公式の仕様ページ（IFrame API）は、この環境から開けなかった。API の名前・速さ・エラー番号・`host`・`playerVars` は、よく知られた使い方から書いている（`ytPlayer.js` の先頭に一覧）。持ち主が公式ページで確かめる。実機の確認は `docs/device-checklist.md` の 35〜48
- 専門の目線のチェック（2026-11-22）は、`docs/safety/content-review.md` の「段6②（YouTube）の 文」の表。9つ すべて 直した（YouTube に 何が 送られるかの お知らせを 練習の 画面にも、足す 画面に `ytRights`、歌う前と結果の画面に 安全の一言、止まったときの文に 次に すること）
- ゆれの目安の 計算（`src/logic/stability.js`）：声の連続を、音の変わり目（中央値から 1半音、または となりの読みから 60セント とんで、3読み 続く）で区切る。1つだけ とんだ読みは捨てる。大きなビブラートの山・谷（100ms 未満で元の高さに戻る）は つなぎ直す。速い曲で 400ms 以上の音が無くても、声があれば「声が 聞こえませんでした」には しない。数字は `CONFIG.stage6.yt`。実機での見え方は確かめ表の 48
- **次**：アプリの中でキーを下げる機能（買った曲だけ。7-3b）
